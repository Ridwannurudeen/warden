# Warden UI audit

Baseline captured 2026-07-13 before the hackathon frontend overhaul on commit `6f33027`.

## Product and technical baseline

Warden is a dependency-free static frontend served beside a FastAPI application. Manual pages live
in `site/`, reason-code documentation is generated by `scripts/build_site.py`, marketplace pages are
generated by `scripts/build_index.py`, and Nginx owns the public clean-URL routing. There is no
JavaScript package manifest, bundler, framework, or type-check command.

Verified baseline commands:

- `python -m pytest -q`: 127 passed; one existing Starlette/httpx TestClient deprecation warning.
- `python -m ruff check .`: clean.
- `node --test tests/js/*.test.js`: 16 passed.
- `python scripts/build_site.py`: 11 reason pages plus the docs index generated.
- `python scripts/build_index.py`: 376 agents indexed, two public-text matches, zero independently
  audited.
- Prettier check: already failing for the existing site JavaScript, JavaScript tests, and stylesheet.
- `nginx -t`: unavailable because Nginx is not installed in the local environment.
- Browser, axe, and Lighthouse automation: unavailable because this session has no connected in-app
  browser. Source, HTTP, local-image, and automated contract checks are the available fallback.

The live public product returned HTTP 200 on every major route during the audit. `GET /health`
returned version `0.1.0`, 122 corpus entries, and four analyzers. The current marketplace snapshot is
dated `2026-07-13T17:45:35Z` and contains 376 agents, two public-text matches, and zero independently
audited agents. Live unpaid requests to `/scan` and `/audit` returned x402 v2 `exact` terms on X Layer
for 0.01 USDT and 0.5 USDT respectively.

## What already works

- Honest `ALLOW`, `SANITIZE`, and `BLOCK` semantics and explicit detector limitations.
- A real free scan route with the 4,000-character and 20-address demo boundaries.
- Current self-only Content Security Policy and no auto-loaded third-party resources.
- Light and dark themes, skip links, visible focus, reduced-motion support, and 44px controls.
- Clear separation between public listing-text signals and authorized endpoint audits.
- Reviewable x402 task commands that keep signing inside the operator's CLI wallet.
- Honest Gauntlet candidate review, badge integrity, status, privacy, and legal boundaries.

## Problems found

### Story and information architecture

Seven equal-weight destinations appear before the product story is established. The homepage has a
strong drain-address example, but it does not yet connect the protected action, runtime distinction,
decision contract, audiences, services, evidence surfaces, and integration path into one judge-ready
sequence. There is no controlled `/showcase` route.

### State and evidence clarity

Verdict, risk, reason, threat class, recommendation, and detector boundary are visually close enough
to be confused. Raw JSON competes with the first-order action. Empty badge and Gauntlet states are
truthful but do not yet feel like deliberate product states. Status has no exact last-check time or
manual retry.

### Data freshness

The homepage no-JavaScript fallback says 375 agents with an older timestamp, while the current
normalized marketplace summary says 376 at `2026-07-13T17:45:35Z`. The hire introduction says six
steps although the verified flow has four. Displayed marketplace and service facts must come from the
committed normalized JSON or carry an explicit dated fallback.

### Interaction and accessibility

The mobile navigation closes on Escape but does not trap focus, restore focus, or close on an outside
interaction. At the smallest breakpoint the visible status text disappears while the dot is hidden
from assistive technology. Light-theme faint text falls below 4.5:1 on common surfaces. Playground
validation and asynchronous states are too coarse, the hire flow is visually CLI-first, and agents
have only two filters with no search or no-results treatment.

### Presentation and production detail

The site lacks canonical, Open Graph, social-card, and structured service metadata. Existing
screenshots predate the current platform and cover only the homepage. The static site has no
production build bundle to measure; performance work therefore centers on small local assets, stable
layout, no external dependencies, and minimal route JavaScript.

## Design-system decision

The visual register is a premium security control room with editorial hierarchy and developer-tool
precision. The foundation is near-black ink, warm off-white text, thin structural rails, compact
technical labels, and restrained elevation. Cyan marks the Warden control surface; green, amber, and
red are reserved for `ALLOW`, `SANITIZE`, and `BLOCK`. The original motif is an action gate: two
vertical rails and a moving payload trace that stops at a central decision cell.

Page archetypes remain distinct. The homepage uses spacious editorial composition; Agents and Status
use denser tabular surfaces; Playground and Integrate use a one-third controls/two-thirds evidence
split; documentation prioritizes navigation and reading measure.

## Benchmark extraction

- Morpho: confident type-led hero, tinted black rather than pure black, restrained secondary text,
  and one dominant composition before supporting evidence.
- Hyperliquid: tabular numerals, compact rows, semantic color, and hover feedback that does not move
  the data layout.
- Stripe Docs: scannable left-side choices paired with a larger runnable evidence panel, clear code
  hierarchy, and restrained elevation on controls.

Only these principles are used. No proprietary artwork, exact layout, or brand treatment is copied.

## Measurable acceptance targets

- First viewport identifies Warden, the protected action, intended operator, and three decisions.
- A real scan is reachable with one primary action and never runs without explicit activation.
- Every dynamic surface has deliberate loading, success, empty, error, and retry messaging.
- All controls remain keyboard operable with visible focus; mobile navigation traps and restores focus.
- Small body and label text meets WCAG 2.2 AA contrast in both themes.
- No verdict or status depends on color alone; reduced motion removes scan and transition animation.
- All existing URLs, API request/response shapes, legal meaning, and CSP boundaries remain intact.
- Marketplace counts, services, prices, and timestamps use one normalized source or dated fallback.
- No production POST, payment, task, review, badge, deployment, or external publication occurs.
- Full Python and JavaScript tests, Ruff, static generation, syntax, resource, and route checks pass.

Failure check: open Warden beside Morpho and Hyperliquid and switch every five seconds. Warden must
not feel smaller, quieter, or less confident; it must still read as a security product rather than a
trading interface.

## Post-build findings

The implementation now uses one grouped Product / Developers / Evidence shell across every public
route, with a persistent live-status affordance, explicit Hire and Run scan actions, canonical and
social metadata, and a keyboard-contained mobile menu. The dependency-free architecture and
self-only resource boundary remain intact.

| Surface          | Before                                                       | After                                                                                                                                         |
| ---------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Homepage         | Reference-portal hierarchy and conflicting snapshot fallback | Five-second outcome story, action-gate proof, explicit three-step runtime boundary, normalized services, and live/honest evidence states      |
| Playground       | Form-first scan with coarse output hierarchy                 | Split editor/result workspace, trusted-recipient chips, verdict-first result, diff, progressive evidence, and typed retry states              |
| Marketplace      | Two filters and blended scan/audit meaning                   | Search, five sorts, separate public-text/audit filters, mobile cards, methodology, and authorized-audit path                                  |
| Gauntlet         | Mechanics and retention appeared after interaction           | Pre-submit policy, consent, safe examples, live counters, candidate/detected/duplicate receipts, and consent-aware retry                      |
| Hire             | CLI wall before operator context                             | Readiness gate, catalog-backed terms, explicit spend boundary, progressive command unlocks, and review-after-verdict gate                     |
| Docs / Integrate | Flat reference pages                                         | Persistent docs navigation, reason matrix, redaction boundary, five accessible integration tabs, and scan/audit-specific response contracts   |
| Badges / Status  | Evidence facts were visually blended                         | Separate integrity/result/target/time panels and clear live-versus-dated status sources                                                       |
| Showcase         | No judge mode                                                | Six predictable scenes, explicit real scan, validated BLOCK/DRAIN_ADDRESS outcome, labeled fallback, reset, and reduced-motion-safe auto mode |
| Privacy / Terms  | Long single reading column                                   | Preserved legal copy with stable section anchors and responsive local navigation                                                              |
