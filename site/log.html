One chain for every signed evidence type

Each entry identifies an APA attestation, an endpoint audit lifecycle event, or a WARDEN BREAKER certificate, then includes the signed record hash and the canonical hash of the preceding log entry.

  1. Ledger entries are unknown until verification is requested.
How chain continuity is checked

The browser starts from the fixed genesis value, hashes each canonical entry, follows every prev_hash, and compares the computed head and entry count with the issuer-signed checkpoint. An external checkpoint, when present, pins an older prefix.

Raw data and tamper test

The raw panel shows the normalized entries this browser verified. Change one byte in a local copy to demonstrate that the signed checkpoint rejects the mutation; the published log is never modified.

What this verification does and does not establish. The live signed head detects changes relative to Warden's locally stored latest state. The public checkpoint history additionally makes replacement and truncation visible relative to any head retained outside Warden. This page verifies a retained head when supplied and says explicitly when none was provided. For either public source, it says explicitly when it is unpublished. The same-origin static history is not independently timestamped or witnessed by itself. A coherent database rollback accompanied by every same-origin copy remains outside this proof without an independently retained head. The result also does not prove log completeness or independently verify each record_hash. This browser view fails closed above 10,000 log or history entries to bound memory, DOM, and request work.
