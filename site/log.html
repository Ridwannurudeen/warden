How continuity is checked

Each entry commits to the one before it.

The browser starts from the fixed genesis value, hashes each canonical entry, follows every prev_hash, and compares the computed head with the issuer-signed checkpoint.

  1. 01Genesis

    Entry one must point to the documented 64-zero start value.

  2. 02Continuity

    Every next entry must point to the prior canonical entry hash.

  3. 03Signed head

    The recomputed head and count must match the signed checkpoint.

  4. 04Published prefix

    An external checkpoint, when present, pins an older prefix.

What this verification does and does not establish. The live signed head detects changes relative to Warden's locally stored latest state. An operator-published checkpoint can additionally pin an older prefix outside that database; this page verifies the pin when one is present and says explicitly when it is unpublished. The static site copy is still not independently timestamped or witnessed. A coherent database rollback remains outside this proof when accompanied by the older static copy. It also does not prove log completeness or independently verify each record_hash. Anyone may preserve a published checkpoint as an independent witness. This browser view fails closed above 10,000 log entries to bound memory, DOM, and request work.
