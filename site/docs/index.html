Detection reference

Eleven reasons Warden can stop or reshape an action.

Each page is tied to a real regression-corpus example and documents the observed verdict, commerce impact, and detector boundary.

Reason codes11
Decision statesALLOW / SANITIZE / BLOCK
EngineDeterministic
PROMPT_INJECTION

Prompt injection

Seller or service text attempts to replace the buyer agent's operating instructions.

Open detection note ROLE_OVERRIDE

Role override

Untrusted content tries to coerce an agent outside its authorized commerce role.

Open detection note WEB3_INJECTION

Web3 injection

Text can induce token approvals, transfers, withdrawals, or other wallet actions.

Open detection note HIDDEN_UNICODE

Hidden Unicode

Invisible characters can conceal or alter listing, address, and response content.

Open detection note ENCODING_TRICK

Encoding trick

Encoded directives can evade a plain-text operator review before payment or execution.

Open detection note STATISTICAL_ANOMALY

Statistical anomaly

Dense imperatives and invisible characters can be mixed into otherwise plausible market copy.

Open detection note CORPUS_MATCH

Corpus similarity match

A rephrased known attack may avoid literal patterns while remaining close to a regression case.

Open detection note DRAIN_ADDRESS

Drain address

A settlement recipient is replaced with an attacker-controlled wallet in untrusted content.

Open detection note TOOL_HIJACK

Tool-call hijack

Untrusted JSON imitates executable tool output and attempts to cross the data/action boundary.

Open detection note SECRET_EXFIL

Secret exfiltration

A response asks an operator or agent to expose wallet or authentication material.

Open detection note MALICIOUS_LINK

Malicious link

An active or deceptive URL can move a buyer from trusted workflow into attacker-controlled content.
