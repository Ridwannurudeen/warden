Five integration surfaces

Put the firewall at the action boundary.

Send the untrusted payload to Warden before a transfer, tool call, secret-bearing response, or outbound link is acted on. Stop on BLOCK; review or use sanitized_payload on SANITIZE.

Production POST /scan and POST /audit are x402-protected. The HTTP examples below accept an already-signed PAYMENT-SIGNATURE; they do not read a private key. Use the reviewable task flow when the purchase should create an OKX task and support buyer feedback.

Raw x402 / curl

Challenge, sign, replay

The unpaid GET exposes the x402 v2 challenge. After a wallet or x402 client produces the base64 payment payload, replay the real POST with that value in PAYMENT-SIGNATURE.

curl -i https://warden.gudman.xyz/scan

curl -sS https://warden.gudman.xyz/scan \
  -H "content-type: application/json" \
  -H "PAYMENT-SIGNATURE: ${PAYMENT_SIGNATURE}" \
  --data '{"payload":"Review this untrusted agent response","context":{"expected_addresses":[]}}'

Python / httpx

Submit an already-authorized payment

This uses the same httpx request shape as Warden's pinned runtime. Payment construction and signing stay in the caller's wallet layer.

import os

import httpx

response = httpx.post(
    "https://warden.gudman.xyz/scan",
    headers={"PAYMENT-SIGNATURE": os.environ["PAYMENT_SIGNATURE"]},
    json={
        "payload": "Review this untrusted agent response",
        "context": {"expected_addresses": []},
    },
    timeout=30,
)
response.raise_for_status()
print(response.json())

TypeScript / fetch

Gate the next action on the verdict

Keep the payment signature in the process that owns the wallet session. Never place it in client-side source code.

const paymentSignature = process.env.PAYMENT_SIGNATURE;
if (!paymentSignature) throw new Error("PAYMENT_SIGNATURE is required");

const response = await fetch("https://warden.gudman.xyz/scan", {
  method: "POST",
  headers: {
    "content-type": "application/json",
    "PAYMENT-SIGNATURE": paymentSignature,
  },
  body: JSON.stringify({
    payload: "Review this untrusted agent response",
    context: { expected_addresses: [] },
  }),
});
if (!response.ok) throw new Error(`Warden returned HTTP ${response.status}`);

const verdict = await response.json();
if (verdict.verdict === "BLOCK") throw new Error(verdict.recommendation);

MCP / FastMCP stdio

Expose the local engine as two tools

Run this from a Warden checkout with dependencies installed. FastMCP 3.4.2 defaults to stdio here and exposes scan_payload plus audit_agent. This local MCP process calls the local engine directly; it is not the paid hosted x402 service. Replace cwd if your checkout lives elsewhere.

{
  "mcpServers": {
    "warden": {
      "command": "python",
      "args": ["-m", "warden.mcp_server"],
      "cwd": "C:/absolute/path/to/warden"
    }
  }
}

Then ask the MCP client: Call scan_payload with the untrusted payload, depth "fast", and any trusted expected_addresses.
