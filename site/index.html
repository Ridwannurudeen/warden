Pre-action security for agent systems

A security boundary for agent actions.

Warden inspects untrusted agent output before it reaches payments, tools, links, or secrets. It returns a policy verdict and an inspectable record.

Request path

              
Place Warden before execution.

            

            

              The caller sends output and context to Warden, receives a
              decision, then applies its own policy before any consequential
              action.
            

          


          

            

              Input
              Agent output
              Untrusted text or tool data
            

            →
            

              Pre-action check
              Warden
              ALLOW · SANITIZE · BLOCK
            

            →
            

              Policy
              Caller decides
              Final authority remains with the caller
            

            →
            

              Execution
              Action
              Payment, tool, link, or secret
            

          


          

            

              ALLOW
              
No implemented detector fired. Caller policy still applies.

            

            

              SANITIZE
              
Review the transformed payload before continuing.

            

            

              BLOCK
              
Do not invoke the proposed action.

            Fast checks cover known patterns. Optional semantic analysis covers
            novel phrasing only when thorough mode is enabled. Evaluation
            figures are dated snapshots, and ALLOW is not a universal safety
            guarantee.
